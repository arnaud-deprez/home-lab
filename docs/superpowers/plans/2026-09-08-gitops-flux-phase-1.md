# GitOps with Flux — Phase 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stand up Flux as the GitOps reconciler on the `laptop` Talos
cluster, migrate the existing local-path-provisioner under Flux, and add
the CloudNativePG operator and Traefik ingress — all reconciled from the
GitHub repo, with SOPS-encrypted secrets.

**Architecture:** Monorepo, Kustomize `base/` catalog + per-cluster
overlays. Flux is bootstrapped against `github.com/arnaud-deprez/home-lab`
at `clusters/laptop`. Two Flux `Kustomization`s per cluster —
`infra-controllers` then `infra-configs` (`dependsOn`) — reconcile the
infrastructure layer. Secrets are encrypted with SOPS + age; the
`kustomize-controller` decrypts them via a cluster Secret.

**Tech Stack:** Flux 2.x, Kustomize, Helm (via Flux `HelmRelease`), SOPS +
age, CloudNativePG operator Helm chart, Traefik Helm chart, Talos Linux
(Flannel CNI, stock PodSecurity: `baseline` enforced everywhere except
`kube-system`).

**Spec:** `docs/superpowers/specs/2026-09-08-gitops-flux-immich-design.md`

## Global Constraints

- Target cluster only: `laptop`. Do not create `hetzner`/`homeserver`
  paths — but do not put laptop-specifics in `base/`.
- Kustomize `base/` holds reusable components; each cluster overlay
  references only the subset it opts into.
- All Flux `Kustomization`s: `prune: true`, `wait: true`,
  `sourceRef` → `flux-system` `GitRepository`, `interval: 10m`.
- Every `HelmRelease` pins an explicit chart version. No `"*"`, no
  floating ranges.
- No remote bases in Flux-reconciled kustomizations — vendor upstream
  manifests into the repo.
- Secrets live only in `*.sops.yaml` files, encrypted before commit.
  The age private key is NEVER committed (add to `.gitignore`) and is
  backed up in the user's password manager.
- `kubeconfig`: `os/context/kubeconfig`. `talosconfig`:
  `os/context/talosconfig`.
- Namespaces that need `hostPort` (Traefik) or host paths
  (local-path-provisioner) must carry
  `pod-security.kubernetes.io/enforce: privileged` — `baseline`
  disallows `hostPort`.
- Commit messages: Conventional Commits. Push after each task so Flux
  reconciles; verify before moving on.
- `age`, `sops`, `helm`, `flux`, `kubectl` are already installed.

## Task 1: Bootstrap Flux against GitHub + wire SOPS

Bootstrap is idempotent and installs Flux's own manifests into the repo,
so it doubles as the "do the controllers reconcile?" check. A short
podinfo test afterwards confirms `helm-controller` and egress to a public
Helm repo work before CNPG depends on them.

**Files:**
- Create: `.sops.yaml`
- Modify: `.gitignore`
- Create: `bootstrap/README.md`
- Generated by bootstrap: `clusters/laptop/flux-system/{gotk-components.yaml,gotk-sync.yaml,kustomization.yaml}`
- Modify (generated): `clusters/laptop/flux-system/kustomization.yaml`

**Interfaces:**
- Consumes: a running Talos cluster reachable via `os/context/kubeconfig`.
- Produces:
  - `GitRepository` named `flux-system` in namespace `flux-system`,
    tracking branch `main`, path `clusters/laptop`.
  - `Kustomization` named `flux-system` (namespace `flux-system`) with
    `spec.decryption` = `{ provider: sops, secretRef: { name: sops-age } }`.
  - cluster Secret `sops-age` in `flux-system` (key: `age.agekey`).
  - `.sops.yaml` rule: files matching `.*\.sops\.ya?ml$` are encrypted
    for the age recipient; only `data`/`stringData` are encrypted.
