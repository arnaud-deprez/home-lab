# TierHive cluster overlay — design

Date: 2026-09-30 · Branch: `feat/tierhive-cluster`

## Goal

Run the laptop stack (Traefik, CloudNativePG, local-path, Pocket ID, Immich, Tailscale
operator) on the single-node Talos VPS at TierHive, reachable on the public internet with
valid HTTPS. Reuse `base/` and overlay only what differs, as `clusters/laptop` does.
The Talos/Kubernetes install is done (see [`docs/tierhive.md`](../../tierhive.md)).

## Decisions

| Topic | Decision | Why |
|---|---|---|
| Domain | `id.vps.powple.com` (Pocket ID), `immich.vps.powple.com` (Immich) | Chosen by the owner; DNS on Namecheap |
| TLS | **TierHive managed HAProxy** terminates TLS and forwards plain HTTP to `10.10.8.2:80` | TierHive assigns public forward ports (e.g. `5777 → 443`); 80/443 cannot be forwarded, so Let's Encrypt HTTP-01 is impossible and Namecheap has no usable DNS-01 path |
| HAProxy set-up | One HAProxy domain entry per hostname; reaches `10.10.8.2:80` directly; HAProxy redirects HTTP→HTTPS | Verified by the owner in the panel |
| cert-manager | **Not installed** on this cluster | Nothing to issue; YAGNI |
| Admin access | Tailscale operator on this cluster; public `6072`/`6075` forwards removed once it works | Owner decision; reduces exposed surface |
| Storage | Keep 5 Gi Immich library and other base PVC sizes | Trial deployment; grow later via overlay |
| Immich ML | Enabled, with memory requests/limits; VM may go to 8 GB | Owner decision |
| Secrets | Separate age key for this cluster; per-cluster secrets live in overlays | Isolates a public VPS compromise from the laptop's secrets |

## Architecture

```
client → HAProxy (TierHive, :443, TLS) → HTTP → 10.10.8.2:80 → Traefik (web) → Pocket ID / Immich
```

Flux tracks `clusters/tierhive/` and reconciles `infra-controllers → infra-configs →
identity / apps`, same `dependsOn` shape as the laptop.

## Changes

### 1. `clusters/tierhive/`
`kustomization.yaml` (with the SOPS decryption patch), `infrastructure.yaml`,
`identity.yaml`, `apps.yaml` — copies of the laptop files with paths
`./infrastructure/{controllers,configs}/tierhive`, `./identity/tierhive`,
`./apps/tierhive`. `flux-system/` is generated by `flux bootstrap --path=clusters/tierhive`,
not hand-written.

### 2. `infrastructure/controllers/tierhive/`
- Resources: `base/cnpg-operator`, `base/traefik`, `base/tailscale-operator`
  (no `cert-manager`), `talos-api-endpoints.yaml` (`10.10.8.2:50000`).
- Traefik patch: DaemonSet, `hostPort` 80 on `web` only, **no** HTTP→HTTPS redirect
  (HAProxy does it; redirecting here would loop), no `websecure` hostPort, and
  `forwardedHeaders.trustedIPs: [10.10.8.0/24]` (the TierHive private network) so
  `X-Forwarded-Proto: https` is honored. Narrow it to the actual HAProxy source address if
  the Traefik access logs show a single one.
- Tailscale patch: distinct names so they do not collide with the laptop on the tailnet —
  `operatorConfig.hostname: tailscale-operator-tierhive` and the Service annotation
  `tailscale.com/hostname: talos-api-tierhive`.
- `operator-oauth.sops.yaml` moves out of `base/` into per-cluster overlays (see §6).

### 3. `infrastructure/configs/tierhive/`
`base/local-path-provisioner` only. No issuer, no CA.

### 4. `identity/tierhive/`
- Base resources plus a patch setting `APP_URL=https://id.vps.powple.com`.
- Ingress `id.vps.powple.com`, `ingressClassName: traefik`, `web` entrypoint, no `tls:`
  section and no cert-manager annotation.
- `pocket-id-secret.sops.yaml` moves out of `base/` into overlays; the tierhive copy has its
  **own** `encryptionKey`.

### 5. `apps/tierhive/immich/`
- Base plus ingress `immich.vps.powple.com` (no TLS section, `web` entrypoint).
- No CA ConfigMap and no `NODE_EXTRA_CA_CERTS`: OIDC discovery to `https://id.vps.powple.com`
  uses a publicly trusted certificate.
- Machine-learning stays on, with memory request/limit set in the HelmRelease patch (values
  chosen at implementation time against the 6 GB node; revisit at 8 GB).

### 6. Secrets and SOPS
- Generate a new age key for tierhive; store it in the `sops-age` Secret in the
  cluster's `flux-system` namespace. Never commit it.
- `.sops.yaml`: path-based rules so `*/laptop/**` secrets use the laptop key and
  `*/tierhive/**` secrets use the tierhive key.
- `git mv` the two base `*.sops.yaml` secrets (`pocket-id-secret`, `operator-oauth`) into
  `laptop/` overlays (same resource names, so the laptop's reconcile is unchanged); create
  tierhive copies with new values. The Tailscale OAuth client for tierhive is created by the
  owner in the Tailscale admin console.
- Any other base `*.sops.yaml` found during implementation gets the same treatment.

### 7. Docs
Update `docs/tierhive.md` (HAProxy, forwards, DNS records, open items), `docs/flux.md` and
`CLAUDE.md` (layout now has two clusters), and `README.md` if it lists clusters.

## Out-of-cluster steps (owner, documented not automated)

1. Namecheap: A/CNAME records for `id.vps` and `immich.vps` as TierHive requires
   (HAProxy domains already added; SSL provisioning in progress).
2. `flux bootstrap` against this repo with `--path=clusters/tierhive`, using the feature
   branch while validating (see CLAUDE.md branch workflow). Point `GitRepository` at `main`
   only after merge, never the other way round.
3. Create the `sops-age` secret with the new key before the first reconcile.
4. Create the Immich OIDC client in Pocket ID and configure it in Immich (UI steps).
5. After Tailscale admin access works, remove the public `6072`/`6075` forwards.

## Validation

Use the `flux-ops` skill: `kustomize build` each new overlay, `helm template` for the
changed HelmReleases, `flux diff` where the cluster is reachable, and confirm the laptop
overlays render identically after the secret moves (`kustomize build` before/after diff).
Live checks: `flux get kustomizations` all Ready, `https://id.vps.powple.com` and
`https://immich.vps.powple.com` load without certificate warnings, OIDC login works, and a
large Immich upload succeeds through HAProxy.

## Risks

- TierHive decrypts all traffic; the hop to the node is plain HTTP on their network.
- Unknown HAProxy upload limits and timeouts — test with a large video early.
- HAProxy and the provider are a single point of failure (public alpha).
- Pocket ID and Immich are internet-facing: review Pocket ID signup/admin settings and
  keep Immich registration closed.
- 6 GB RAM is tight with Immich ML; watch memory and raise to 8 GB if needed.

## Out of scope

Bulk storage/second worker, cert-manager on tierhive, changes to the laptop cluster's
behavior, automating DNS.
